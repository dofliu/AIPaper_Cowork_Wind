## 一、這回答的是哪一個問題

`docs/FREEZE_LOCKIN_FINDINGS.md` 已經**實證**了凍結期誤報率 0.6819 是選擇效應
而非停滯：它在凍結的頭 18 步就已經是 0.589，而且 α 動 50 倍它幾乎不動。

兩者都是觀察。審稿人可以全盤接受，然後問下一個很自然的問題：

> 選擇往哪裡去？6-of-18 這條規則**本身**強制出多高的比率？
> 0.68 是高於還是低於那個值？

在今天以前，本專案沒有數字可以回答。本輪產出一個，而且是**證明**而不是量測——
所以答案不依賴分數串流的任何模型、不依賴校準層是對的、也不依賴 CARE v6。

## 二、下界（完整推導見工具的 module docstring）

在**已校準點**的索引空間裡（那才是告警規則活動的空間）令 `e_t ∈ {0,1}` 為超越、

```
S_t = e_t + e_{t-1} + ... + e_{t-w+1}          w = 18
F   = { t : S_t >= k }                          k = 6
```

`F` 就是凍結集——這不是近似，是等號：`regime_conditional_calibration.py`
是在 `e_t` 進入視窗**之後**才設 `frozen`（第 280–284 行接第 290 行）。於是

```
k|F| <= Σ_{t∈F} S_t = Σ_i e_i·m_i <= w·Σ_{i∈N(F)} e_i
⟹   Σ_{i∈N(F)} e_i  >=  (k/w)·|F|
```

其中 `N(F)` 是凍結點**連同每次凍結事前看的那最多 17 點**。
推導裡沒有任何一步用到資料的性質。

### 這個界**不是**什麼

- **不是**凍結集本身的下界。那種下界不存在：連續 6 次超越後全靜默，會產生
  18 個凍結點卻只含 1 次超越，比率 0.056。1/3 屬於**視窗**，而 `N(F)` 正是
  把視窗還原回來。工具的 T3 就是這個反例，用來釘住這句話。
- **不是**分解。「觀測值減下界」**不等於**「停滯的那一份」。下界只說觀測值
  不可能更小，對餘量的組成一無所知。工具刻意不替餘量貼標籤。

## 三、結果（91 案裡的 47 個正常案例，D1/D6 排除四案、case 93 裁切 18 列）

| α | 凍結佔比 | \|F\| | 凍結 run 數 | \|N(F)\| | **下界（N(F) 上）** | 下界／α | 實測（N(F) 上） | 實測／下界 |
|---|---|---|---|---|---|---|---|---|
| 0.001 | 0.47% | 11,726 | 222 | 15,307 | **0.2554** | 255× | 0.6590 | 2.58 |
| **0.01** | **4.94%** | **123,005** | **3,025** | **171,071** | **0.2397** | **24×** | **0.5741** | **2.40** |
| 0.05 | 23.39% | 579,642 | 12,831 | 771,223 | **0.2505** | 5.0× | 0.6060 | 2.42 |

**兩件事值得注意，而且方向相反：**

1. **下界本身幾乎不隨 α 動**（0.2397–0.2554，變動 6.5%），儘管 α 動了 50 倍、
   凍結佔比動了 50 倍。它是那條告警規則的結構常數，不是資料的性質。
2. **下界相對 α 的倍數卻動了 51 倍**（5× → 255×）。所以「凍結期誤報率遠高於
   名目值」這件事在 α 越小的時候越是**被規則保證**的，不是越可疑。

**實測／下界穩定在 2.40–2.58**——實測值跟著結構下界走，不是跟著 α 走。
這與 FINDINGS 2.3 的 α 不變性是同一個現象的兩種量法，但這一次有代數保證墊底。

## 四、前提稽核 — 本輪最容易被忽略的一項結果

下界只有在 `frozen` 真的等於 `S_t >= 6` 時才成立。那是從**原始碼**讀出來的，
而原始碼會與實際跑出來的東西漂移。所以工具對每一個可測試的已校準點重算 `S_t`，
**兩個方向都查**：

| α | 可測試點 | 標了 frozen 但規則說不該 | 規則說該但沒 frozen |
|---|---|---|---|
| 0.001 | 2,491,778 | **0** | **0** |
| 0.01 | 2,489,541 | **0** | **0** |
| 0.05 | 2,477,654 | **0** | **0** |

**約 250 萬個點、三個 α、雙向零違反。** 這同時是對「已簽核的 6-of-18 真的被
執行了」的一次獨立驗證——先前沒有任何一支工具查過這件事，它一直是靠讀程式碼相信的。

## 五、一個定義差異，先寫下來免得日後被當成矛盾

本工具報 α=0.01 最長凍結 run = **1,711**；
`PROJECT_STATUS` 第 1 節與 `FREEZE_LOCKIN_FINDINGS` 報 **1,712**。

**兩個都是對的，量的是不同的東西**：本工具在**已校準點**空間數（那是告警視窗
所在的空間），既有工具在**資料列**空間數。已實測確認該次凍結中間夾了
**恰好一列**未校準列（暖機列的 `frozen` 旗標照樣被寫成 1，但它沒有 `exceed`，
不進告警視窗）。已在本檔案與 `FREEZE_LOCKIN_FINDINGS` 註明，
避免下一個人把 1,711 與 1,712 當成其中一份算錯了。
